The cache that never grows — and the memory that never forgets to blend.

the one-sentence claim this artifact teaches A fixed-shape recurrent state can process a sequence of unbounded length without allocating a new memory slot per token — but unlike a growing key–value cache, it forgets by blending old and new information together instead of by deleting it outright.

Below is a real, running memory system — not an animation of one. Drag the sliders and watch two different ways of remembering a conversation fail in two completely different ways.

Why this is worth 12 minutes right now

Every Transformer answering a long conversation is quietly paying rent: each new token adds one more key and value vector to a cache that never shrinks. StreamingLLM and H2O both exist because that rent becomes unpayable at long context lengths, and both solve it the same structural way — decide which tokens to evict.

Pathway's Dragon Hatchling (BDH) line of work asks a different question: what if the architecture never grows a cache in the first place, and instead keeps a fixed-size associative state that gets updated on every token? BDH-CQ, the reasoning variant built on BDH, reports a 150M-parameter model reaching 29.5% pass@2 on the public ARC-AGI-1 evaluation set at roughly $0.0007 per task by leaning on exactly this kind of recurrent, additive memory instead of a growing context.[BDH-CQ] That is a genuinely different point on the cost–accuracy map, and it is why "does memory have to grow with context length" is an active, not settled, question in 2026.

The rest of this page lets you build both kinds of memory with your own hands, at toy scale, and watch exactly where each one breaks.

Part 2 — What's actually being computed

KV cache (Transformer-style)

Every token's key/value pair is appended to a list. To answer a query, find the stored key most similar to the query and return its value. If the capacity is full, the oldest entries are silently evicted — a hard, all-or-nothing cliff. This is exact recall of whatever survives, and total memory loss of whatever doesn't.

Recurrent fast-weight state

A single fixed-size matrix S (D×D) accumulates every fact additively:

S ← S + value·keyT   (after every token)
estimate = S·query

Every fact leaves a trace in every entry of S. Recall is never exact — it's a superposition, and it degrades gracefully as more facts compete for the same D-dimensional space, rather than dropping off a cliff.

This additive update rule is the standard "fast weight programmer" / linear-attention memory (Schmidhuber, 1992; and the family of linear-attention models surveyed alongside BDH's own GPU-friendly formulation). It is exactly the family of mechanism that BDH-CQ's paper places its own contextual memory within, describing the special case where "state accumulates additively per demonstration." It is not the literal BDH architecture — see the disclosure box in Part 3.

Part 3 — Where BDH and BDH-CQ actually fit

the required BDH module — grounded in the primary papers, not a secondhand summary

BDH doesn't manage a key–value cache at all. It replaces the cache with a form of the same idea you just played with above, but implemented very differently, and for a different reason.

what BDH actually says (primary source: arXiv:2509.26507) Dragon Hatchling (BDH) is a graph of n locally-interacting "neuron particles" whose working memory during inference entirely relies on synaptic plasticity with Hebbian learning — connections between neurons strengthen when those neurons are co-active, the classic "neurons that fire together, wire together" rule. The paper reports that activation vectors are sparse and non-negative (empirically, on the order of 5% of neurons active at once, varying with how predictable the input is) and that individual synapses become monosemantic — a given synapse reliably strengthens whenever the model processes one particular concept. The neuron interaction graph itself is scale-free with a heavy-tailed degree distribution: most neurons have few connections, a few become hubs. A GPU-friendly formulation, BDH-GPU, implements this via ReLU-based low-rank transformations combined with linear attention — the paper is explicit that this should not be read as a state-space model in the Mamba sense, even though it is described as an "attention-based state space sequence learning architecture."

What's changing as BDH reads a sequence is synaptic strength (the graph's edge weights) — not a growing list of stored tokens, and not the model's trained parameters. That is the same structural move you just tested in Part 1: a fixed-size store that is updated, not appended to. The difference from our toy matrix S is that BDH's update is sparse, non-negative, and driven by genuinely local Hebbian dynamics across a large neuron graph — not a dense outer product over a handful of random Gaussian vectors.

what BDH-CQ adds (primary source: arXiv:2608.09888) BDH-CQ is a 150M-parameter reasoning system built on BDH that stores in-context demonstrations directly in its recurrent memory as it reads them, then solves a query through iterative computation in continuous latent space — without ever writing out a verbal chain of thought. On the public ARC-AGI-1 evaluation set it reports 29.5% pass@2 (24.25% pass@1) at a computed cost of about $0.0007 per task, which the authors and independent commentary describe as pushing past the previously reported cost–accuracy frontier for that benchmark. Critically for our claim: BDH-CQ adapts to a brand-new task with no parameter updates and no evaluation-task demonstrations seen during training — the adaptation lives entirely in the evolving recurrent state, which is precisely the "state changes, weights don't" distinction that Part 1's charts are built around.
evidence discipline — what this result is and isn't The 29.5% pass@2 figure is developer-reported, from Pathway's own technical report (arXiv:2608.09888). That same paper states it was checked by a "black-box audit" run without access to model weights — but the auditors, Remigiusz Kinas (Bielik AI) and Richard Zhong (NYU), are themselves two of the paper's nine co-authors, not an unaffiliated third party. A documented, no-weights-access protocol is a real and meaningful constraint against simply making the number up, but it is not the same as an independent, non-affiliated replication, and it does not resolve open questions about training-data composition or checkpoint selection. Treat 29.5% as a developer-reported figure with an in-house black-box check, not as an externally validated benchmark result or a deployed real-world outcome.
disclosure — toy model vs. official BDH The interactive demo in Part 1 is an original, minimal illustration of the additive/linear-attention family of memory that BDH-CQ's paper explicitly relates itself to. It is not a reimplementation of BDH or BDH-CQ, does not use their published equations, code, or checkpoints, and should not be read as reproducing any of their reported numbers. Real BDH activations are sparse and non-negative and operate over a large neuron graph with Hebbian, not dense-outer-product, updates. We built our own toy specifically so this page does not depend on the unavailable BDH-CQ checkpoint, per the track's own rules.

Part 4 — Where this explainer can be wrong (please try to break it)

limitation 1 Our toy vectors are random and (nearly) orthogonal by construction. Real transformer keys are highly structured and correlated, so real attention-sink and eviction behavior (StreamingLLM, H2O) is messier than the clean "hard cliff" shown here — eviction quality depends heavily on which heuristic decides what to keep.
limitation 2 Real BDH's capacity does not come from D≈10–24 dense dimensions — it comes from a much larger, sparse neuron graph, so the exact "N/D" collapse point you can find on this page has no direct numeric correspondence to BDH's real capacity.
common misconception "Recurrent memory forgets because it has less capacity than a cache." Not quite — for small D relative to N, both mechanisms lose information. The real difference this page teaches is the shape of forgetting: a cache forgets by hard, discrete eviction; a fast-weight/BDH-style state forgets by soft, graceful interference. Neither is strictly "better" at remembering — they trade differently.
try to falsify the claim Set the cache to "unlimited" and push N far past D. The cache should stay at 100% while the recurrent state degrades — that's the claim. If you find a setting where the opposite happens (recurrent beats an unlimited cache), you've found either a bug or a genuinely interesting edge case — either way, that's a real result, not a scripted one.
